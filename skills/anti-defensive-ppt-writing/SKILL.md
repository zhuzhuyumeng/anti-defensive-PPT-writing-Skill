# PPT 内容叙事与展示原则

让观众沿着有证据支撑的主线，理解最值得记住的判断，并知道它与自己有什么关系。围绕观众的任务组织材料，减少无关辩解，保留影响判断的事实与边界。

## 适用边界

- 负责内容取舍、叙事顺序、页面信息层级与证据展示。只需内容时直接交付可用文案，不引入制图、编程或联网依赖。
- 保留用户指定的模板、页数、章节、语言和术语。复盘可以保留过程，教学可以循序解释，答辩与审计须回应规定问题。
- 用户要求实际 PPTX、HTML 幻灯片或修改现有文件时，继续完成对应文件；配合环境中可用的制作能力，不以内容大纲代替成品，不跳过该工具要求的渲染检查。

## 工作方式

### 1. 找到观众的任务

先读材料及已有页面，提取：谁看、为什么看、听完需要理解或决定什么、时长或页数、必须保留什么。已有信息不重复询问。

普通偏好缺失时，简述假设后继续，如“先按面向非技术管理者的 10 分钟汇报组织”。缺少关键事实时标明缺口，先完成能写的部分。只有一个题目时可做结构与待补证据清单，不编造业绩、研究结果或客户案例。

区分现场讲解与独立阅读：演讲版将推导放进讲述提示；阅读版补足理解所需的上下文。页数由内容、时长与用户要求共同决定，不机械套用“每分钟一页”。

### 2. 匹配主张与证据

形成一句核心信息：**对象或问题 + 有依据的判断 + 对观众的意义**。尚未验证的方案写成建议或待验证假设。

从材料里找最有用、证据最扎实的信息，不把所有工作平均分配页面。核对关键判断的依据与范围，区分事实、解释和建议：材料直接记录了什么；由此能推出什么；接下来希望做什么。

证据不足时缩小主张或标明待验证。没有可靠优势时，如实呈现现状、取舍和待解决的问题，不强造“领先”“突破”或“全面提升”。

选择适合任务的路径，不强制填满固定章节：

| 场景 | 可采用的推进方式 |
| --- | --- |
| 决策或方案汇报 | 建议与依据 → 备选方案和取舍 → 资源、风险与决策请求 |
| 研究或技术分享 | 问题与缺口 → 方法或机制 → 结果及适用边界 → 意义 |
| 业务复盘 | 目标与实际 → 差异及原因 → 有效做法 → 纠偏与下一步 |
| 产品展示 | 用户任务 → 使用过程 → 可验证的效果 → 适配条件与下一步 |
| 教学或知识讲解 | 学习目标 → 核心概念 → 例子或演示 → 练习与迁移 |

### 3. 落到每一页

先列页面职责，再写标题、文案与展示方式。只读标题也应能理解主要推理，不能靠讲述者临时补出缺失的逻辑。需要校准标题、证据表达或特殊场景时，读取 [references/examples.md](references/examples.md)。

## 十二条规则

1. **一页服务一个主要问题。** 多个证据可以共同支持一个判断；两个独立结论可拆页，重复表达可合并。封面、导航、参考文献和附录不硬套结论页。
2. **标题传递信息。** 证据充分时写具体判断，如“审批等待占总耗时的 60%”，少用“背景介绍”“效果分析”。待决定的内容可用明确问题或建议，教学可用引导问题。标题强度不超过证据。
3. **按理解或决策所需排序。** 优先建立关键理解，再补背景。不默认从公司历史、宏观背景或项目时间线讲起；需要复盘过程时，说明关键节点怎样改变了结果。
4. **上屏文案直接可用。** 写具体对象、变化、原因或行动，减少无解释的口号。编辑任务放在说明字段，不混入正式文案；缺数据明确占位，不用漂亮话填空。
5. **分清上屏、讲述与备查。** 主结论和关键证据上屏；推导、过渡和例子可进讲述提示；完整明细可进附录。影响判断的风险、比较条件和适用范围必须在相关页面可见，不能只藏在备注或附录。
6. **图表有论证职责。** 说明观众要看什么关系，它支持什么判断。比较可用条形图或同口径表格，趋势用折线图，过程用流程图，机制用关系图。没有数据不画虚构数据图；概念示意须明确标注。
7. **指出证据中的重点。** 明确要高亮的对象、差距或转折，用标注解释意义；保留单位、时间、样本量、分母、基线和来源。不要让观众自己从密集表格寻找贡献。
8. **同口径比较。** 并列相关优势与代价，说明条件。不得混用时间段、更换分母、截断坐标或挑选样本制造胜出；不得把相关性、局部试点或模拟结果写成已证实的因果或普遍成效。
9. **准确表达限制。** 删除没有信息量的道歉和自我贬低；保留真实失利、负向结果和重要不确定性。例如写“本次覆盖同领域数据，跨领域效果待验证”，不扩大成整体否定，也不改写成未经验证的优势。
10. **密度服从阅读任务。** 拥挤时先删无关信息，再缩短或拆页，不靠缩小字体解决取舍。阅读版可保留更多解释；条款、定义等必要长内容须保留原义。无需统一成三条要点或固定字数。
11. **承接推动理解。** 下一页回答上一页留下的问题，或提供下一层证据。章节页只在有导航价值时保留，不换个标题重复结论。
12. **收尾完成观众的任务。** 汇报给出结论与具体请求；技术分享指出证明了什么及适用范围；教学回到目标与应用。可保留用户要求的礼仪性结束页，在此前完成实质收束，不临时加入新主张。

## 默认交付

按请求交付：只改一页就只改一页，只要大纲就不强加逐字稿。完整内容稿默认包含一句核心信息、叙事顺序和逐页内容；假设与待补项集中简述。

逐页可采用以下结构，省略无用字段，不为填模板重复信息：

```text
第 X 页｜可直接上屏的标题
页面任务：观众在本页需要理解或决定什么
上屏内容：可直接使用的文案、数字或图内标签
展示建议：具体的信息关系、视觉重点与必要标注
证据与边界：来源、关键口径及限制；缺失时注明待补
讲述提示：上屏之外需要解释的内容或过渡（按需）
```

“证据与边界”中的重要限定必须同时体现在上屏文案或图表标注中；来源注记也应可随页面使用。只需内容时，展示建议写到能交给设计者执行即可，不展开字体、阴影或动画参数。

缺失事实用 `[待补：具体字段]`，上下文也保持待确认状态。例如“标题草案：试点后处理时间下降 [待补：幅度]”，不能把未确认的占位结论写成确定标题。说明结构的示例数据须就地注明“虚构示例，不用于正式展示”。

改写已有材料时，可简述实质变更理由，如合并重复结论、前移证据、纠正过度推断，不默认输出冗长诊断。用户要成品文件时，上述结构可作为内部规划，不额外交付未请求的中间文件。

## 交付前自查

- 顺读标题，主线能否成立？每页是否提供新判断、证据或必要解释？
- 重要结论是否有依据？有没有把建议、设想或示例写成事实？
- 压缩后，数字、单位、出处、比较口径和关键限定是否还在？
- 文案能否直接使用？展示建议是否说清看什么，而非只说“做得高级”？
- 是否遵守页数、时长、章节和保留项？是否完成请求的文件交付？
- 负向结果与关键风险有没有被“突出优势”掩盖？收尾是否完成沟通任务？
